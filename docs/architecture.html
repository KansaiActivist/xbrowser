ウィンドウとタブ

メインウィンドウ (WS_POPUP, GDI で枠を自前描画) ├─ アドレスバー (EDIT 子コントロール) ├─ タブ1 ─ 子 HWND ─ WebView2 コントローラ ├─ タブ2 ─ 子 HWND ─ WebView2 コントローラ └─ …

タブごとに別の WebView2 コントローラを持ちますが、同一プロファイルのデータフォルダは共有するため、裏側の Edge プロセスやログインセッションは 1 つにまとまります。Win32 のメッセージループと WebView2 (COM) は同じ OS スレッドで動く必要があるため、main の先頭で runtime.LockOSThread() を呼んでいます。

ローカルページ (設定・スタート)

  • HTML は //go:embed で実行ファイルに同梱し、NavigateToString で表示します。
  • 表示直前に /*__STATE__*/null と /*__I18N__*/ を、現在の状態 (JSON) と翻訳テーブルに置換します。
  • ページ → Go は window.chrome.webview.postMessage で {type, data} の JSON を送ります。ローカルページ用のメッセージは、タブの種類 (kindWeb / kindStart / kindSettings) が一致するときだけ受け付けます。
  • Go → ページは window.__setState(...) と window.__toast(...) を Eval で呼びます。
  • 背景画像は仮想ホスト https://xbrowser.local/ を %LocalAppData%\XBrowser\StartBg に割り当てて配信します。

テーマ

プリセットは dark / light / system。system はレジストリの AppsUseLightTheme を読み、WM_SETTINGCHANGE で Windows 側の変更に追従します。

翻訳の流れ

  1. ページ内の JS が選択テキストを translate で送り、「翻訳中…」のポップアップ (Shadow DOM) を出します。
  2. Go が goroutine で translate.googleapis.com に問い合わせます。COM は UI スレッドからしか触れないため、結果は WM_APP メッセージで UI スレッドに戻してから Eval でページへ渡します。
  3. ページ側は id が現在のポップアップと一致する結果だけを表示します (古い結果は無視)。

通信はアプリ本体だけが行うため、X のページに外部への通信を許可する必要はありません。

セキュリティ上の作り

  • WebView2 の chrome.webview は第三者の iframe からも呼べるため、ページからのメッセージは種類ごとにタブの種類・大きさ・値を検証します。設定を変える操作は設定タブからしか受け付けません。
  • xbrowser:// はどのサイトからも呼べるため、受け付けるのは「共有 (https://x.com/intent/post を開くだけ)」と「X のドメインを開く」だけで、受け取る項目と長さも絞っています。
  • 閉じる・最小化・最大化・タブの × は、マウスを離したときに実行します。押した瞬間に実行すると、アプリが消えたあとの「離す」操作が背後のウィンドウ (エクスプローラーのタブの × など) に届いてしまうためです。
  • 起動引数・転送された URL・「新しいタブで開く」は、X のドメイン (https) だけを受け付け、数と頻度も制限します。
  • タブの URL として保存するのは http / https だけです。
  • 設定ファイルは一時ファイルに書いてから置き換えるため、書き込み中に終了しても壊れません。
  • debug.log は 1MB を超えると次回起動時に作り直し、ページから届いたメッセージの中身は記録しません。

既知の制限

  • 外部リンクの判定はクリックと window.open ベースです。location.href によるスクリプト遷移やサーバーリダイレクトは検知できない場合があります。
  • レイアウトは固定ピクセルで、高 DPI への対応は簡易的です (window.go の定数で調整可能)。
  • 通知バッジと X 側のテーマ連動は、X の DOM / クッキー仕様に依存します。
